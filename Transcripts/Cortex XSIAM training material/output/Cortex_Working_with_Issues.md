## Common Issue Objects

By analyzing an issue, you can better understand the cause of what happened in full context to validate whether an issue requires additional action.

### Common to All License Types

Common issue-related objects that are available for all license types:

- **Issue** — An issue is a notification type of data to report a suspicious activity or an event.
- **Case** — A case is a container object to group-related issues as well as other attack-related data.
- **Log** — A log is any data collection of name-value pairs; values may not be atomic but multiple values.

### Available with XDR Pro Endpoints

Issue-related objects that are available with XDR Pro endpoints:

- **Stitched Issues** — A stitched issue is an issue enhanced by Cortex, which is automatically correlated with logs to provide better attack visibility.
- **Causality Group Owner (CGO)** — CGO is the process identified as root cause of an attack; the initiator.
- **Causality View** — This view is the name of a management console page specialized for causality analysis of issues, in particular stitched issues.

## Key Issue Attributes

The Issues table contains the following key attributes:

*[Diagram: Issues table with annotated call-out bubbles pointing to each column header. Sample row shown: CATEGORY=Execution, ACTION=Detected, ISSUE ID=300, NAME=A TCP stream was creat..., STATUS=In Progress, SEVERITY=Medium (orange), OBSERVATION TIME=May 27th 2021 10:27:13, ISSUE D...=Security, DESCRIPTION=A TCP stream wa...]*

| Attribute | Description |
|---|---|
| **Category** | This is a classification of the suspicious activity that triggered the issue. It is based on the issue source and type such as malware or exploit. |
| **Issue ID** | This ID is a unique key generated by Cortex during the issue creation to identify the issue. |
| **Status** | This column shows the status of the issue such as New, In Progress, or Resolved. |
| **Observation Time** | This column shows the time when the issue was created. |
| **Updated Issue Fields** | Mousing over this icon shows recent field changes. |
| **Action** | This column shows the action taken by the issue generator when the issue occurred such as prevented, detected, etc. |
| **Name** | This column displays the name of the issue. |
| **Severity** | This column displays the severity level of the issue such as Informational, Low, Medium, or High. |
| **Description** | This column displays additional information about the issue. |

## External ID Attribute

An issue's External ID is generated by the issues source; therefore, this attribute is external to the Cortex instance. The External ID column is hidden by default; you can enable this column from the Layout Manager.

In case the source is the Cortex XDR agent, this ID is known as the prevention ID. The image shows the Prevention folder on the endpoint, which contains a subfolder that has the same name as the External ID displayed in the Issues table. The Cortex XDR agent created this subfolder when it generated the issue.

## Actions on Issues

An issue's shortcut menu displays the applicable actions whose availability vary depending on the source and category of the issue and whether the issue was stitched with the endpoint data.

### Investigate Causality Chain

From the Investigate Causality Chain menu, you have the option to open the issue in Causality View or Timeline View in a new browser tab or in the same tab.

*[Screenshot: Right-click shortcut menu showing: Change Status, Change Severity, Change Assignee, Investigate Causality Chain (highlighted), Run Automation, Manage Issue, Retrieve Additional Data, Pivots to views, Create Case, Copy text to clipboard. Sub-menu: Open Card in new tab, Open Card in same tab, Open Timeline in new tab.]*

### Manage Issue

Under Manage Issue, you can select **Create exclusion rule** to put the rule that caused the Cortex XDR agent to trigger the issue into silent mode so it does not fire issues. You can use **Exclude Issue** to exclude the issue from the investigation.

*[Screenshot: Right-click menu showing Manage Issue (highlighted) with sub-menu: Exclude Issue, Link to case, Create exclusion rule. Full menu visible: Change Status, Change Severity, Change Assignee, Run Automation, Manage Issue, Pivots to views, Investigate in XQL query, Create Case, Copy text to clipboard.]*

### Retrieve Additional Data

Under the Retrieve Additional Data option, you have two options:

- **Retrieve issue data**: This option retrieves additional data about the activity such as process memory dump from the endpoint.
- **Retrieve related files**: This option initiates retrieval of the attack-related files, mainly the executables.

*[Screenshot: Right-click menu showing Retrieve Additional Data (highlighted) with sub-menu: Retrieve issue data, Retrieve related files.]*

### Pivots to Views

Under Pivots to views, you can select **Investigate** option to view and manage the issue in more detail or **Open Host Risk View** to view additional host risk information.

*[Screenshot: Right-click menu showing Pivots to views (highlighted) with sub-menu: Open Host Risk View, View related case, Show Workplan, Investigate.]*

## Starred Issues

An issue starring is a rule to star and prioritize an issue. A starred issue also prioritizes their hosting cases.

You can add a starring policy in **Cases & Issues > Case Configuration > Starred Issues**. As rule criteria, select some actions using filters.

> **Note:** An issue exclusions rule takes precedence over an issue starring rule if the same issue matches to both.

*[Screenshot: Case Configuration > Starred Issues page showing "Found 3 results" and "+ Add Starring Configuration" button. Table columns: STAR ID, MODIFICATION TIME, NAME, DESCRIPTION, COMMENT, USER, STATUS. Three rows:*
- *Star ID 3, Mar 26th 2025 10:54:07, Star - 5, severity = Critical, Enabled*
- *Star ID 2, Mar 26th 2025 10:50:44, Star - 3, severity = Medium, Enabled*
- *Star ID 1, Mar 25th 2025 17:34:39, Star - 1, severity = High, Enabled]*

### Creating New Issue Starring Rules

To create a new issue starring, navigate to **Cases & Issues > Case Configuration > Starred Issues**. Click **+ Add Starring Configuration** and define policy rule criteria using issue attributes.

On the Create New Issue Starring Configuration window, you can use the filter button to select the attributes and specify the values. Alternatively, you can select an existing issue in the Issues table, open the shortcut menu, and perform the Add issues with or Add issues without action.

> **Note:** The Configuration Name (also known as rule name) is auto-filled.

*[Screenshot: New Issue Starring Configuration form with filter criteria builder visible.]*

## Featured Issue Fields Overview

You use the featured issue fields to easily locate and prioritize issues with specific values. The featured issue fields are Host, User, and IP Address.

### Functionality

The featured issue fields provide similar functionality as filtering in the Issues table for those featured issue fields, and then you sort or filter the Issue table on those provided issue fields. Consider how challenging creating filter criteria for a list of 100 hostnames would be. You can instead use the featured issue fields to prioritize issues based on hostnames.

### How to Use

To benefit from this feature, you first add new featured field values to any of the featured issue fields, and then you sort or filter the issue table on those provided issue fields.

For example, you can add a list of hostnames as the featured issue field values of the Host type. Then, to prioritize or better highlight issues that contain any one of the values you added, you use the provided issue fields to sort or filter.

## Add New Featured Field Values

To add new featured field values, go to **Cases & Issues > Case Configuration > Featured Fields** and click one of the available featured value options: Hosts, Users, and IP Addresses. Each option has its own page, which opens on the right.

In this example, the steps to add a featured host value are as follows:

1. Click **Hosts** on the left navigation.
2. On the Hosts page, click **+ Add featured Hosts**.
3. Select **Create New** or **Upload from File**. To add more values, click **Add**.
